### 한 줄 소개

학생이 교내 시설·장비를 직접 찾거나 이용 목적에 맞는 추천을 받아 필요한 항목을 선택·신청하고, 관리자가 승인·거절, 장비 출고·반납 및 시설 이용을 관리하는 웹 기반 정보시스템입니다.

장비는 이동형 디지털카메라·이동형 빔프로젝터·무선 마이크 고정 세트를 대상으로 합니다. 시설은 공간 전체를 예약하며, 현재 시연에는 스터디룸·회의실·촬영실의 가상 데이터를 사용합니다. 실제 학교의 반출 가능 품목과 운영 정책은 확인 필요입니다.

## 2. 프로젝트 배경 및 목적

### 2.1 해결하려는 문제

시설 예약과 장비 대여 정보가 여러 채널에 분산되어 있다면 학생은 이용 가능한 자원을 찾거나 각각 문의하는 데 불편을 겪을 수 있습니다. 관리자는 신청·승인·실제 이용·반납 및 장비 상태를 함께 확인하기 어려울 수 있습니다.

희망 자원을 이용할 수 없을 때 학생이 다른 일정이나 같은 용도의 자원을 반복 조회해야 할 수 있습니다. 또한 처음 이용하는 학생은 '학생회 회의', '과제 영상 촬영'처럼 활동 목적은 있어도 어떤 공간이나 장비가 필요한지 정하기 어려울 수 있습니다.

위 불편은 사용자 인터뷰로 검증되지 않은 가정입니다. 기존 공개자료 조사에서는 한남대학교의 시설 예약 안내와 비치 장비 정보를 확인했으나, 실제 반출 대여 목록과 이용자 불편을 확인한 것은 아닙니다. 기존 온라인 예약 서비스가 없거나 모든 업무가 수작업이라고 주장하지 않습니다. 조사 기록은 7.3항에 구분합니다.

### 2.2 프로젝트 목적

- 이용할 자원을 아는 학생에게는 장비·시설의 직접 검색과 목록 선택을 제공합니다.
- 자원 선택이 어려운 학생에게는 활동 내용과 인원 등에 맞는 시설·장비 및 추천 이유를 제공합니다.
- 필요한 항목을 선택 목록에서 확인하고, 장비·시설의 조건을 구분하여 신청하도록 합니다.
- 이용 불가 시 같은 자원의 다른 일정과 같은 일정의 대체 자원을 비교하도록 합니다.
- 관리자가 승인·거절, 실제 장비 전달, 구성품 확인, 반납·보류·재확인 및 시설 이용을 처리하도록 합니다.
- 주요 화면은 기능별로 분리하고 상세 확인·조건 변경은 패널이나 팝업을 활용하여 반복 이동과 입력을 줄입니다.

### 2.3 기대효과

- 학생이 목적·인원·사양·구성품에 맞는 자원을 선택할 수 있습니다.
- 조회·추천·선택·인증 과정에서 입력한 조건을 유지할 수 있습니다.
- 승인 대기와 실제 예약 확보를 구분하고 중복 승인을 방지할 수 있습니다.
- 출고 당시 구성품 정보를 보존하여 반납 확인 기준을 일관되게 유지할 수 있습니다.
- 누락 구성품, 반납 보류 사유 및 추가 반환 내역을 같은 대여 건에서 확인할 수 있습니다.
- 학생이 자신의 신청 현황·과거 신청 내역과 관리자 거절 사유를 확인할 수 있습니다.
- 시설·장비를 한 시스템에서 조회하여 반복 탐색과 문의를 줄이는 것을 기대합니다.

효과는 아직 검증되지 않았습니다. 사용자 시험을 진행하면 탐색 시간·신청 완료 여부·반복 조회 및 문의 횟수 등을 기록하고, 내부 기능 시험과 실제 사용 효과를 구분합니다.

## 3. 주요 사용자

| 사용자 유형 | 사용자 설명 | 주요 목적 |
| --- | --- | --- |
| 학생 | 교내 시설·장비를 이용하려는 대학생 | 직접 검색, 목적별 추천, 선택 목록 관리, 신청·승인 전 취소, 신청 현황·과거 내역 확인, 거절·보류 사유 확인, 장비 반납 신청 |
| 관리자 | 시설 예약과 장비 대여 업무를 처리하는 담당자 | 신청 승인·거절, 장비 출고·반납·추가 반환 확인, 장비 점검 상태 관리, 시설 이용 시작·종료 확인, 현황·이력 조회, 후속 정보 관리 |

처음 이용하는 학생과 경험이 있는 학생은 동일한 학생 Actor입니다. 비로그인 상태에서도 조회·추천·상세 확인·선택을 허용하고, 신청·개인 내역·관리자 업무에는 인증과 권한 검사를 적용합니다. 관리자는 사전 준비된 별도 계정을 사용하며 일반 회원가입에서 관리자 권한을 선택하지 않습니다.

관리자는 시스템의 업무 역할이며, 실제 학교에서 시설과 장비를 같은 부서가 담당한다는 의미는 아닙니다.

## 4. 핵심 서비스 시나리오

### 4.1 학생 장비 대여

1. 학생이 장비 대여 화면에서 품목을 검색하거나 목록을 확인합니다.
2. 수령 예정일·시간과 반납 예정일·시간을 지정합니다. 간편 대여기간을 선택하면 반납 예정 시점을 계산하고 총 대여기간을 표시합니다.
3. 모델·주요 사양·개별 관리번호·구성품·이용 가능 여부를 확인하고 필요한 항목을 선택합니다.
4. 선택 목록에서 항목별 장비와 일정을 확인한 후 별도 신청 버튼을 누릅니다.
5. 필요한 경우 로그인·회원가입을 진행하며 입력과 선택을 유지합니다. 인증 성공만으로 신청하지 않습니다.
6. 학생이 최종 제출하면 시스템이 최신 조건과 이용 가능 여부를 검사하여 승인 대기 신청을 저장합니다.
7. 관리자가 승인하거나 필수 사유와 함께 거절합니다. 승인 대기는 장비를 확보한 상태가 아닙니다.
8. 승인에 성공하면 해당 개별 장비의 기간을 확보합니다. 실제 전달 시 구성품 검수를 거쳐 출고·대여 중으로 기록합니다.
9. 학생이 자신의 대여 중 항목에 반납을 신청하고, 관리자가 실제 반환을 확인합니다.
10. 학생은 신청 현황 또는 과거 신청 내역에서 처리 결과를 확인합니다.

### 4.2 목적별 시설·장비 추천

1. 학생이 목적별 대여 화면에 '학생회 회의 6명' 등 활동 내용과 이용 이유를 입력합니다.
2. 시스템이 정의된 키워드·용도 규칙으로 활동을 해석하고 필요한 공간과 추가 장비를 추천합니다. 목적 이름만 자동 선택하고 끝내지 않습니다.
3. 명확한 참여 인원이 있으면 인원 입력에 제안합니다. 학생이 직접 수정한 인원은 동일 활동의 재조회에서 유지합니다.
4. 일정이 없어도 인원·용도에 맞는 준비 구성을 안내합니다. 예를 들어 6명 회의에는 4명 시설을 후보로 제시하지 않습니다. 일정 미입력 상태에서는 예약 가능이 확정되었다고 표시하지 않습니다.
5. 일반적인 영상 촬영이나 복수 목적처럼 의미가 모호하면 짧은 추가 확인을 받습니다. 인터뷰로 임의 확정하지 않습니다.
6. 활동 목적 없이 자원명만 입력한 경우에는 해당 장비·시설의 직접 검색으로 연결합니다. 미인식 입력에도 직접 검색·목록 선택 경로를 제공합니다.
7. 학생이 장비 대여기간과 시설 이용 시간·인원·목적을 각각 입력하면 시스템이 해당 조건의 가능 여부를 확인합니다.
8. 추천 이유·수용 인원·위치·비치 설비·주요 사양을 확인하고 필요한 항목만 선택 목록에 담습니다.
9. 선택 목록 확인·인증·최종 제출을 거쳐 개별 신청을 생성합니다. 추천된 항목을 자동 신청하거나 일괄 승인하지 않습니다.

### 4.3 선택 목록 관리

1. 학생이 직접 조회 또는 추천 결과에서 필요한 장비·시설을 체크하여 담습니다.
2. 선택 목록에서 항목을 추가·제거하고 각 항목의 이용 조건을 확인합니다.
3. 장비의 수령·반납 일정과 시설의 이용 시간·인원·목적을 구분하여 보존합니다. 다른 종류의 조건을 임의로 덮어쓰지 않습니다.
4. 조건이 변경되거나 항목이 이용 불가이면 현재 화면의 패널에서 수정하거나 대체 자원을 비교합니다.
5. 학생이 별도 신청 버튼을 누르면 인증 상태와 최신 가능 여부를 확인합니다.
6. 최종 제출 후 실제 저장 결과를 안내합니다. 같은 접수 묶음에 있어도 각 항목의 승인·거절·이용 상태는 독립적입니다.

### 4.4 학생 시설 예약 및 이용

1. 학생이 시설 예약 화면에서 시설을 검색하거나 목록을 확인합니다.
2. 이용 날짜·시작 및 종료 시각·인원·목적을 입력합니다.
3. 시스템이 운영 시간·수용 인원·허용 용도·승인된 예약·이용 제한을 확인합니다.
4. 학생이 시설을 선택하고 선택 목록·인증·최종 확인을 거쳐 신청합니다.
5. 시스템이 승인 대기 신청을 저장하고, 관리자가 최신 조건을 재확인하여 승인하거나 사유와 함께 거절합니다.
6. 승인 시 해당 시설의 이용 시간을 확보합니다. 승인 전에는 자신의 신청을 취소할 수 있습니다.
7. 관리자가 실제 이용 시작과 종료를 확인하여 기록합니다. 예정 시각 경과만으로 자동 완료하지 않습니다.
8. 학생은 자신의 예약·이용 내역을, 관리자는 시설별 현황·이력을 확인합니다.

### 4.5 장비 이용 불가 시 다른 대여 기간 조회

1. 희망 기간에 장비를 이용할 수 없으면 학생이 같은 장비의 다른 대여 기간 조회를 선택합니다.
2. 시스템이 동일한 개별 장비와 기존 대여 길이를 유지하여 검색 구간 내 가능한 기간을 빠른 시작 순으로 제공합니다.
3. 학생이 기간을 선택하면 선택 목록·대여 신청에 변경 조건을 전달합니다.
4. 결과가 없으면 없다고 안내하고, 신청·승인 시 가능 여부를 다시 검사합니다.

### 4.6 장비 이용 불가 시 대체 장비 조회

1. 학생이 기존 대여 기간을 유지하려고 대체 장비 조회를 선택합니다.
2. 시스템이 미리 지정된 동일 용도 대체 관계 중 기존 기간 전체에 이용 가능한 장비를 제공합니다.
3. 학생이 주요 사양·구성품·지정 이유·차이를 확인하고 장비를 선택합니다.
4. 기존 기간과 선택 장비를 신청에 전달합니다. 대체 장비 선택만으로 예약을 확보하지 않습니다.

### 4.7 시설 이용 불가 시 다른 이용 시간대 조회

1. 학생이 같은 시설을 유지하려고 다른 이용 시간대 조회를 선택합니다.
2. 시스템이 동일 시설·이용 길이·인원·목적을 유지하여 운영 조건과 승인 예약에 맞는 다른 시간대를 제공합니다.
3. 인원·목적처럼 시간을 바꾸어도 충족되지 않는 조건이 있으면 가능한 시간대라고 표시하지 않습니다.
4. 학생이 선택한 시간대를 시설 예약 신청에 전달하고 신청·승인 시 재확인합니다.

### 4.8 시설 이용 불가 시 대체 시설 조회

1. 학생이 기존 이용 시간을 유지하려고 대체 시설 조회를 선택합니다.
2. 시스템이 기존 시작·종료 시각·인원·목적을 충족하고 운영·예약 제한에 맞는 다른 시설을 제공합니다.
3. 위치·수용 인원·허용 용도·비치 설비 차이를 확인하고 시설을 선택합니다.
4. 조건에 맞는 결과가 없으면 없다고 표시합니다. 선택만으로 시설을 확보하지 않습니다.

### 4.9 관리자 장비 출고 처리

1. 관리자가 승인된 장비 신청에서 수령 확인을 선택합니다.
2. 실제 전달할 본체·구성품의 이름·필수 수량·전달 수량·상태를 확인합니다.
3. 정해진 고정 세트의 필수 수량과 정상 상태가 충족되지 않으면 출고하지 않습니다.
4. 시스템이 해당 대여 건의 출고 구성품 정보를 별도 보존하고 실제 출고 시각·처리자·대여 중 상태를 함께 저장합니다.
5. 이후 기본 구성품 목록이 바뀌어도 이미 보존한 출고 기준은 변경하지 않습니다.

### 4.10 관리자 반납 관리 및 보류

1. 관리자가 학생의 반납 신청을 열고 해당 건에 보존된 출고 기준을 확인합니다.
2. 실제 반환된 본체·구성품의 수량·상태를 대조합니다.
3. 필수 반환이 모두 확인되면 반납 완료와 처리자·시각을 기록합니다.
4. 필수 구성품이 누락되면 누락 품목·부족 수량·사유를 저장하고 반납 보류로 처리합니다. 본체도 필수 구성품 확인 대상입니다.
5. 보류 건은 학생의 신청 현황에 남기고 사유를 표시합니다. 장비에는 이용 제한을 적용합니다.
6. 모두 반환되었어도 손상이 있으면 대여 건의 반납 완료와 장비의 점검 중 상태를 구분합니다.

### 4.11 관리자 추가 반환 재확인

1. 학생이 누락 구성품을 추가 반환하면 관리자가 같은 반납 보류 건에서 추가 반환 재확인을 선택합니다.
2. 시스템이 최초 출고 기준과 이전 회차의 누적 반환 수량을 제공합니다.
3. 관리자가 이번에 추가 반환된 수량·상태를 확인합니다. 이전 반환 수량을 중복 합산하지 않습니다.
4. 반환 수량이 출고 수량을 초과하거나 필수 확인이 누락되면 저장하지 않습니다.
5. 아직 부족하면 반납 보류를 유지하고 사유·확인 회차·처리자·시각을 추가 기록합니다.
6. 필수 반환이 모두 확인되면 반납 완료로 전환합니다. 학생이 새 대여·반납 신청을 만들지는 않습니다.
7. 보류로 설정된 장비 점검 제한은 자동 해제하지 않으며, 반환 해결 후 관리자의 점검 완료 확인을 거칩니다.

### 4.12 관리자 점검 및 저장 충돌 처리

1. 관리자가 점검 필요 사유와 실제 확인 내용을 기록하여 장비 이용을 제한합니다.
2. 미반환·반납 보류가 남아 있으면 점검 완료만으로 제한을 해제하지 않습니다.
3. 반환 해결·장비 정상 상태를 확인하고 점검 완료를 기록한 경우에만 제한을 해제합니다.
4. 승인·검수 등 저장 시 최신 신청 상태와 버전을 확인합니다. 다른 창의 처리로 기준이 바뀌면 이전 입력으로 성공 처리하지 않습니다.
5. 검수 충돌 후에는 '최신 상태로 다시 확인'을 통해 최신 대여 건·장비 상태·누적 반환량을 불러와 다시 확인합니다. 이전 검수 체크를 새 확인의 결과로 재사용하지 않습니다.
6. 이미 완료되어 해당 작업을 할 수 없으면 최신 결과만 안내합니다. 저장 실패를 처리 완료로 표시하지 않습니다.

| 출발 유스케이스 | 관계 | 대상 유스케이스 | 조건 또는 의미 |
| --- | --- | --- | --- |
| 다른 대여 기간 조회 | `<<extend>>` | 장비 조회 및 상세조회 | 희망 기간에 이용 불가이고 학생이 다른 기간 조회를 선택 |
| 대체 장비 조회 | `<<extend>>` | 장비 조회 및 상세조회 | 희망 기간에 이용 불가이고 학생이 대체 장비 조회를 선택 |
| 다른 이용 시간대 조회 | `<<extend>>` | 시설 조회 및 상세조회 | 희망 조건에 이용 불가이고 학생이 다른 시간대 조회를 선택 |
| 대체 시설 조회 | `<<extend>>` | 시설 조회 및 상세조회 | 희망 조건에 이용 불가이고 학생이 대체 시설 조회를 선택 |
| 장비 출고 처리 | `<<include>>` | 출고 구성품 정보 보존 | 실제 전달한 구성품 정보를 해당 건에 보존 |
| 반납 관리 | `<<include>>` | 출고 기준 반환 확인 | 최초 반납 시 출고 기준과 실제 반환을 대조 |
| 추가 반환 재확인 | `<<include>>` | 출고 기준 반환 확인 | 같은 출고 기준과 이전 누적 반환량을 사용 |
| 반납 보류 처리 | `<<extend>>` | 반납 관리 | 필수 구성품 누락 시 수행 |

반납 관리의 확장점은 `반환 확인 후 결과 처리`, 보류 조건은 `필수 구성품 누락`입니다. 추가 반환 후에도 부족하면 F29의 결과 흐름에서 보류를 유지합니다.

관계선은 이용 순서를 나타내지 않습니다. 추천→선택 목록→신청이라는 화면 순서만을 이유로 `include`나 `extend`를 추가하지 않습니다. 로그인 필요 여부는 각 기능의 사전조건으로 명세합니다.

네 가지 이용 불가 대체 조회는 목적별 추천과 별도 기능입니다. `extend` 관계라고 해서 선택 구현 기능이 되는 것은 아니며 F16·F17·F25의 필수 범위를 유지합니다.

## 6. 개발 범위

### 6.1 장비 분류와 실물 관리

아래는 개발용 가상 대여 품목입니다. 공개자료에 비치된 사실과 실제 반출 대여 가능 여부를 구분합니다.

| 분류 | 품목 | 고정 세트의 구성 기준 | 주요 사양·비교 항목 |
| --- | --- | --- | --- |
| 촬영 | 이동형 디지털카메라 | 본체·기본 렌즈·배터리·충전기 | 사진·영상 해상도, 촬영 용도, 렌즈, 연결 단자 |
| 영상·발표 | 이동형 빔프로젝터 | 본체·전원선·영상 케이블·세트에 지정된 리모컨 | 해상도, 밝기·측정 단위, 입력 단자, 제공 케이블 |
| 음향 | 무선 마이크 | 개별 세트에 지정된 마이크 수량·수신기·전원 구성품 | 마이크 개수, 동시 채널 수, 출력 단자, 전원 방식 |

- 동일 모델도 개별 관리번호로 구분하고 수량은 개별 자산을 기준으로 집계합니다.
- 본체를 포함한 구성품별 식별값·필수 수량을 등록합니다. 마이크가 2개인 세트를 1개 기준으로 검수하지 않습니다.
- 구성품 단독 대여와 임의 세트 조합은 제외합니다.
- 모델 사양과 개별 장비의 구성품·상태·보관 장소를 구분합니다.
- 가상 모델·사양·관리번호는 시연용임을 표시하고 실제 확인되지 않은 값을 학교 실물 정보로 사용하지 않습니다.
- 삼각대·발표 리모컨의 별도 대여·휴대용 스피커·노트북은 초기 별도 대여 품목에 포함하지 않습니다.

현재 시연 데이터에는 카메라 2세트, 프로젝터 2세트, 마이크 3세트가 있습니다. 이 중 마이크 한 세트는 점검 상태입니다. 모델과 수량 모두 가상이며 실제 학교 재고가 아닙니다.

### 6.2 시설과 비치 설비

시설은 좌석별 배정 없이 공간 전체를 예약합니다. 현재 시연 시설은 회의실 2곳, 스터디룸 1곳, 촬영실 2곳의 가상 데이터입니다.

| 시설 유형 | 주요 이용 목적 | 조건·안내 정보 |
| --- | --- | --- |
| 회의실 | 팀 회의·발표 연습 | 인원, 운영 시간, 허용 용도, 테이블·화이트보드·화면 등 |
| 스터디룸 | 팀 활동·회의·발표 연습 | 인원, 운영 시간, 허용 용도, 비치 PC 등 |
| 촬영실 | 인터뷰·과제 영상 촬영 | 인원, 운영 시간, 허용 용도, 고정 조명·방음 등 |

촬영실은 현재 Make에 있는 가상 공간을 반영한 것으로, 실제 중앙도서관 셀프스튜디오 업무를 재현한다고 확정한 것은 아닙니다. 비치 설비는 시설 상세의 안내 정보로 제공하고 같은 실물을 별도 대여 재고로 중복 등록하지 않습니다.

비치 설비 고장으로 이용 목적을 충족하지 못하면 시설 제한 관리 대상으로 삼되, 해당 운영 편집 화면은 F21의 후속 개발 범위입니다. 대운동장·VR Lab은 초기 구현 대상에서 제외합니다.

### 6.3 승인 및 예약 확보

1. 장비·시설 모두 승인 대기는 미확보입니다. 겹치는 승인 대기 신청이 존재할 수 있습니다.
2. 장비는 개별 관리번호, 시설은 시설 ID로 중복을 검사합니다.
3. 승인 결과와 기간 확보는 하나의 처리 단위로 저장합니다. 동시 승인에서도 겹치는 승인이 모두 성공하면 안 됩니다.
4. 승인 실패 시 성공으로 표시하지 않고 최신 상태와 사유를 안내합니다. 충돌한 다른 승인 대기 신청을 자동 거절하지 않습니다.
5. 학생은 자신의 승인 대기 신청만 취소할 수 있습니다. 이 취소는 확보 재고를 해제하는 작업이 아닙니다.
6. 출고·이용 시작 후에도 원래 확보 기간을 유지합니다. 조기 반납·종료로 남은 기간을 자동 해제하지 않습니다.
7. 실제 미반납·보류·시설 종료 지연은 예정 종료 시각만으로 해결되었다고 간주하지 않습니다.
8. 상태 제한으로 기존 승인 예약이 영향을 받으면 관리자에게 안내하고 실제 출고·이용 시작 가능 여부를 다시 확인합니다. 자동 취소·자동 자원 변경은 하지 않습니다.
9. 승인 후 취소·미수령·미이용의 권한과 확보 해제 기준은 확인 필요입니다.

기간은 시작 포함·종료 제외로 계산합니다. 준비·정리 시간이 없으면 기존 종료 시점과 새 시작 시점이 같을 때 겹치지 않습니다. 준비·정리 시간은 적용 여부를 정한 뒤 조회·신청·승인·대체 조회에 동일하게 반영합니다.

### 6.4 반납 보류·추가 반환·점검

- 최초 반납과 추가 반환 모두 해당 건의 출고 기준을 사용합니다.
- 확인 회차마다 이번 반환 수량·누적 수량·남은 수량·상태·확인자·시각을 보존합니다. 이전 기록을 덮어쓰지 않습니다.
- 본체 또는 필수 구성품이 부족하면 반납 보류로 유지하며 강제로 반납 완료하지 않습니다.
- 보류 건은 신청 현황에 남기고 학생에게 부족 품목·수량·사유를 표시합니다.
- 보류·미반납·점검 제한 장비는 신규 신청·승인·출고 및 이용 가능한 대체 후보로 사용하지 않습니다.
- 추가 반환이 모두 확인되면 대여 건은 반납 완료로 전환합니다. 보류로 설정한 점검 제한은 별도 점검 완료 확인 전까지 유지합니다.
- 모두 반환되었어도 손상이 있으면 반납 완료와 장비 점검 중을 함께 기록할 수 있습니다.
- 점검 완료는 미반환·보류가 해결되고 기본 운영 상태도 정상인 경우에만 허용합니다.
- 별도 연체 목록·통계·알림은 F14·F15의 선택 범위이며, 기본적인 미반납·보류 제한은 필수 범위입니다.
- 분실 확정·배상·대체품 수용·미반환 강제 종결은 제외합니다.

### 6.5 출고 구성품 정보 보존

1. 기본 구성품은 개별 장비·고정 세트에 등록합니다.
2. 실제 출고 때 본체와 구성품별 필수 수량·전달 수량·정상 상태를 확인합니다.
3. 해당 대여 건에 구성품 식별값·이름·수량·상태·확인자·시각과 실제 출고 정보를 별도로 저장합니다.
4. 필요한 검수가 누락되거나 정해진 수량·정상 상태를 충족하지 않으면 출고하지 않습니다.
5. 기본 구성품 목록을 변경해도 과거 출고 기준을 변경하지 않습니다. 출고 완료 후 임의 편집을 허용하지 않습니다.
6. 반납·추가 반환은 보존된 출고 기준을 공통으로 사용합니다.
7. 기존 진행 건에 출고 기준이 없으면 관리자가 근거를 확인하여 '사후 등록 기준'으로 구분합니다. 실제 출고 당시 등록된 것처럼 소급 표시하지 않습니다.
8. 출고 기준이 없는 과거 완료 건은 그대로 보존하며, 자동 기준 생성이나 완료 건 재개방을 하지 않습니다.

| 대체 시설 조회 | 기존 시작·종료 시점·인원·목적 | 시설 | 수용 인원·허용 용도·운영 시간·예약·이용 제한 |

장비 대체 관계는 방향별로 지정합니다. A→B가 있다고 B→A를 자동 생성하지 않습니다. 현재 시연에서는 미리 정의한 관계를 사용하며 관리자 편집 화면은 후속 개발합니다. 시설 대체는 인원·목적·운영 조건으로 판단하며 장비 관계를 그대로 적용하지 않습니다.

결과가 없으면 없다고 안내합니다. 유지 조건을 임의로 바꾸거나 사용자의 선택 없이 자원을 변경하지 않습니다. 신청·승인 시 최신 가능 여부를 다시 검사합니다.

### 6.10 화면과 사용자 이동

- 홈·장비 대여·시설 예약·목적별 대여는 각각 독립된 주요 화면으로 이동합니다.
- 장비·시설 화면은 직접 검색과 목록 선택을 중심으로, 목적별 화면은 활동 입력과 추천 이유를 중심으로 구성합니다.
- 상세·대체 자원·다른 일정·조건 수정·안내·인증·신청 확인은 현재 흐름의 패널·팝업을 활용합니다.
- 체크는 선택 목록에 담는 동작이며 신청 완료가 아닙니다. 별도 신청 버튼과 최종 확인을 둡니다.
- 장비에는 수령·반납 예정 시점과 총 대여기간을, 시설에는 이용 시간·인원·목적을 표시합니다.
- 같은 활동에서 학생이 직접 수정한 인원을 재검색으로 덮어쓰지 않습니다.
- 인증·상세 확인·일반 저장 실패에서 입력·선택을 가능한 한 유지합니다. 검수 충돌 후 최신 기준으로 다시 여는 경우에는 재확인이 필요함을 안내합니다.
- 대여기간·수령·반납 안내는 입력란 가까운 짧은 설명이나 도움말로 제공합니다. 공지·Q&A 전체 시스템을 별도 필수 기능으로 추가하지 않습니다.

진행 건은 '신청 현황', 종료 건은 '과거 신청 내역'에서 항목별로 표시하고 장비·시설 필터를 제공합니다. 같은 접수 묶음 안에서도 항목별 상태에 따라 다른 탭에 나타날 수 있으며 원래 항목 번호를 유지합니다.

대여 건 상태와 장비 자체의 정상·점검·사용 중지 상태를 구분합니다. 시설에는 장비의 수령·반납 문구를 사용하지 않습니다. 학생은 승인·거절·검수·점검 완료·시설 이용 완료를 직접 처리하지 않습니다.

### 7.4 시연 저장·검증의 범위

구현 현황은 제공된 `Implement CampusRent Home Screen (1)(2).zip`의 코드 검토를 기준으로 정리합니다. 실제 Figma 공유 링크가 이후 변경되었다면 해당 버전과 다시 비교합니다.

- 가상 신청·검수·장비 상태는 같은 출처의 브라우저 IndexedDB에 저장합니다.
- 최신 읽기·버전 검사·변경 저장을 트랜잭션으로 처리하고 기존 전체 배열을 덮어쓰는 저장 방식으로 되돌리지 않습니다.
- 신청 항목과 장비 상태의 버전을 확인하여 오래된 화면에서 변경한 결과가 최신 처리를 덮어쓰지 않도록 합니다.
- 검수 충돌 후 명시적으로 최신 기준을 다시 선택하며, 새 확인에는 최신 누적 반환량을 사용합니다.
- 시연 인증은 실제 서버 계정·영구 회원가입·기기 간 공유를 의미하지 않습니다. 새로고침 후 인증 및 계정 유지에는 시연 구조의 제한이 있습니다.
- 활동 인식·인원·검수 재선택 관련 일부 자동 시험은 확인했으나 전체 브라우저·다중 탭·실제 사용자 시험을 모두 완료한 것은 아닙니다.
- 코드 안의 시험 완료 기록과 별도로 팀이 실제 실행한 환경·결과·실패 항목을 테스트 문서에 남깁니다.

브라우저 역할 검사는 실제 서버 접근 통제를 대신하지 않습니다. Spring Boot·Oracle 연동과 서버 배포는 별도 구현·검증 대상으로 유지합니다.

- 예약 확보 여부는 개별 신청 항목의 자원·기간·처리 상태를 기준으로 판단합니다. 승인 대기는 기간을 확보하지 않으며, 승인 시 중복 검사·상태 변경·이력 저장을 함께 처리하도록 구현합니다.
- 기본 구성품과 대여 건별 출고 구성품 정보를 분리하여 보존합니다. 반납 확인 회차와 구성품별 이번 반환 수량을 기록하고 누적 반환 수량·부족 수량은 보존된 기록을 기준으로 계산합니다.
- 실제 출고 시각과 사후 등록 여부를 구분하며, 사후 등록한 정보를 실제 출고 당시 기록으로 표시하지 않습니다.
- 현재 선택 목록 테이블은 로그인 후 서버 저장을 지원하는 경우를 가정합니다. 비로그인 선택은 브라우저 임시 저장으로 구분합니다. 서버 저장 범위를 확정하면서 테이블 유지 여부를 검토하며, 변경 시 테이블 수와 관련 문서도 함께 갱신합니다.

논리·물리 ERD 초안 작성과 실제 데이터베이스 구축·검증은 구분합니다. UQ·CHECK·기본값의 모델·SQL 반영 여부, 장비·시설 중 하나만 선택하는 조건, 시작·종료 시각과 상태 전이, 동시 승인 중복 방지는 후속 확인 항목입니다. 테이블 정의서는 교수님 안내에 따라 ERD 검토·확정 후 작성합니다.

- Commit은 로컬 저장소의 변경 이력 기록, Push는 원격 저장소 반영, Pull은 원격 변경 사항을 가져와 통합하는 작업으로 구분합니다.
- 기능별 독립 작업이 필요하면 최신 main을 기준으로 브랜치를 생성하고 변경 내용을 검토하여 통합합니다. 모든 작업에서 새 브랜치를 의무적으로 만들지는 않습니다.
- Commit 메시지에는 변경 내용과 작업 목적을 기록합니다. 문서 수정과 기능 개발의 담당자·결과를 추적할 수 있도록 합니다.

- 일정 미입력 추천을 예약 가능 확정으로 표시하지 않습니다.
- 선택 목록 추가·제거·항목별 조건 보존이 가능하고, 체크·추천·로그인만으로 신청하지 않습니다.

#### 신청·승인·권한

- 신청·개인 내역·관리자 업무에 역할·소유권 검사를 적용합니다.
- 자신의 승인 대기 항목만 취소할 수 있고 취소된 신청은 다시 승인하지 않습니다.
