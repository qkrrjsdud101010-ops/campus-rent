# 2026-11-17 CampusRent 대화·작업 기록

사용자는 지난 공유 이후의 대화와 포스터 산출물을 로컬 Git으로 커밋하고 GitHub에 푸시하도록 승인했다. 이 문서는 11월 16일 포스터 제작부터 11월 17일 교수님·팀원 피드백 반영까지의 주요 결정과 결과를 요약한다.

## 포스터 초안 제작과 참고 자료 검토

공지의 가로 60cm × 세로 85cm 규격으로 CampusRent 포스터를 제작했다. 팀은 New-Era이며 박건영 PM, 김세종 Backend·DB, 박준서 Frontend·UI로 표기했다.

초기 구성에는 서비스 소개, 기획 단계의 문제 가설, 목적별 추천, 출고 기준을 보존하는 반납·추가 반환 관리, 처리 흐름, 개발 스택, 기대효과를 담았다. 다른 팀의 Red 포스터를 참고해 실행 화면·데이터 구조·검증 결과의 제시 방식을 검토하고, 실제 개발 성과를 보강한 초안을 만들었다.

공유하는 이전 초안은 실제 PK·FK를 기준으로 주요 테이블 7개를 발췌한 요약 ERD, 시스템 구성, 검증 결과를 포함한다. 전체 스키마의 26테이블·17시퀀스와 주요 관계를 SQL에 대조했다. 상세 컬럼과 일부 관계의 생략 범위를 표시했다.

포스터는 로컬에서 PDF·SVG·PNG로 제작했다. 다른 팀의 참고 PDF와 개인 폴더의 원본 문서는 참고 자료로 검토했다.

## 실제 서버 화면과 검증 결과의 출처

11월 16일에는 실제 Oracle 개발 서버를 실행해 목적별 추천과 관리자 장비 관리·편집·구성품 화면을 캡처했다. 초기 가상 장비·시설을 조회했으며 캡처 후 관리자 세션을 종료했다.

검증 수치의 시점과 범위를 재확인했다. 11월 16일 작업 기록은 앞서 수행한 결과를 요약한 기록이며, 포스터에 제시한 다음 검증은 2026년 11월 12일 Java 25 환경의 결과다.

- 단위 테스트 18개는 기존 대여 정책 7개와 장비 입력 정책·서비스 회귀 11개를 포함한다.
- 장비 관리 API 11개는 검증 시나리오의 수다.
- Chrome 화면 13개는 검증 항목의 수다.

이번 포스터 공유 과정에서는 기존 검증 기록과 산출물의 내용·파일 상태를 확인했다. 실제 학교 운영정책 확인, 사용자 평가, 외부 배포는 후속 과제로 다룬다.

## 교수님 피드백과 화면 중심 재구성

사용자는 포스터 두 개를 교수님께 보냈고, 화면이 더 돋보이도록 색을 조정하고 개발 배경에 맞는 화면을 보여 달라는 의견을 전달했다.

기존 초안은 추천과 관리자 장비 편집 화면이 중심이었다. 개발 배경의 세 문제와 직접 대응하는 화면을 같은 행에 배치하도록 구성을 바꿨다.

| 기획 단계의 문제 가설 | 대응 기능과 화면 | 강조색 |
| --- | --- | --- |
| 무엇을 빌려야 할지 고르기 어려움 | 목적·인원 기반 추천과 추천 이유 | 파랑 |
| 원하는 자원을 이용하기 어려워 다시 탐색함 | 대체 시설 후보와 다른 일정·기간 비교 | 청록 |
| 신청 이후 진행과 반환 상태를 확인하기 어려움 | 학생 신청 현황과 관리자 반납 검수 | 주황 |

밝은 중립 배경에 진한 화면 프레임을 배치하고 화면 영역을 확대했다. 추천은 11월 16일 실제 서버 캡처를 사용했다. 대체 시설·일정 변경·신청 현황·반납 검수는 10월 화면설계서에서 추출한 시연 이미지를 사용하고 각 영역에 출처를 표기했다. 화면 안의 자원·일정·신청 정보는 가상 자원 또는 시연 데이터다.

개발 스택과 검증 결과, 데이터 흐름도는 하단에 요약했다. 이를 통해 개발 배경에서 화면으로 시선이 이어지도록 구성했다.

## 팀원 피드백과 하단 간결화

팀원은 구현 기반과 QR이 복잡해 보인다는 의견을 제시했다. 이를 검토한 뒤 사용자가 수정 반영을 요청했다.

- QR과 긴 GitHub 주소를 포스터에서 제거했다.
- 구현 기반 제목과 여러 줄의 기술 목록을 `Spring Boot · Thymeleaf · Oracle 11g XE` 한 줄로 축약했다.
- 검증 결과는 날짜와 함께 단위 테스트 18개, 장비 관리 API 11시나리오, Chrome 화면 13항목을 한 줄로 표시했다.
- 하단 데이터 흐름도를 정리하고 확보한 공간으로 화면을 조금 더 확대했다.
- 팀명과 팀원 정보를 가운데 정렬하고 하단을 밝은 배경과 간단한 구분선으로 마무리했다.

최신 반영본은 PDF 한 페이지, 600 × 850mm이며 미리보기는 1800 × 2550px다. 한글 글꼴 포함, SVG의 화면 이미지 7개 포함, 제목·본문의 겹침과 잘림, QR·주소 제거를 확인했다.

## 공유 산출물

| 버전 | PDF | SVG·PNG |

PDF는 인쇄·제출용, SVG는 텍스트·도형 편집 원본, PNG는 검토용 미리보기다. SVG에는 화면 캡처가 이미지로 포함되며 한글 글꼴은 맑은 고딕 또는 Noto Sans KR을 사용한다.

## 로컬 작업과 Git 공유 원칙

**각자 VS Code의 로컬 작업 폴더에서 수정하고 로컬 Git으로 커밋·푸시한다. GitHub에 직접 로그인해 브라우저에서 파일을 수정하지 않는다.** 사용자가 이번 공유 요청에서도 이 원칙을 다시 확인했다.

공유 범위는 README, 이번 대화·작업 기록, 두 버전의 PDF·SVG·PNG 여섯 파일과 `.gitattributes`다. 기존 Git 설정에서 PDF가 텍스트로 인식되어 형식 검사에서 PDF 내부의 유효한 공백까지 검사하는 문제를 확인했다. `output/pdf/*.pdf`에 바이너리 속성을 지정해 텍스트 변환과 줄바꿈 변경 없이 파일을 보존하도록 했다.

실제 DB·앱 접속 정보는 Git 제외 로컬 설정에서 관리하며 `.work/`의 런타임·검증용 임시 파일과 원본 참고 자료는 로컬에서 관리한다.
