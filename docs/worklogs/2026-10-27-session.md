## 확정한 개발 방향

- 최종 화면 기술은 HTML·CSS·JavaScript·Thymeleaf, 서버는 Java·Spring Boot, DB는 Oracle입니다.
- Make의 React·TypeScript·Tailwind·Vite 코드는 시연·원본 화면 자료로 활용합니다.
- 현재는 화면부터 구현합니다. 임시 저장으로 흐름을 확인한 뒤 서버 인증·서비스·DAO·Oracle에 연결합니다.
- 목적별 추천은 활동 키워드·용도·인원에 따른 규칙 기반입니다. 별도 AI 추천 모델을 도입하지 않습니다.
- JDK·Spring Boot·Oracle 버전, MyBatis/JDBC 선택, 배포 환경은 팀 기준으로 확정할 항목입니다.

## 화면 구현 결과

공통 HTML은 `src/main/resources/templates/index.html`, 정적 자원은 `src/main/resources/static/`에 배치했습니다. Thymeleaf용 정적 자원 경로를 준비했지만 현재 미리보기는 Spring Boot·Thymeleaf 엔진 대신 화면 확인용 Java 서버로 실행합니다.

- 홈: 활동 입력·추천 키워드, 장비·시설 바로가기, 활동별 구성·이용 절차
- 장비·시설: 원본 장비 7개·시설 5개, 검색·분류·일정·이용 조건·상세·대체 자원·다른 일정 조회
- 목적별 대여: 활동 분석·확인 질문·추천 이유, 시설 수용 인원, 수동 인원 유지와 조건 변경 후 재조회
- 공통 선택 목록: 항목별 조건 보존·수정·제거, 신청 시 인증, 별도 최종 제출
- 학생 내역: 진행·과거 내역 구분, 승인 전 취소, 반납 신청, 처리 사유·원래 항목 번호
- 관리자: 개별 승인·거절, 출고 기준 보존, 반납 보류·추가 반환·점검, 시설 실제 이용 시작·종료
- 원본 SVG 14개와 로컬 폰트 3개 반영, 데스크톱·모바일 화면 확인

시연 로그인·가입 계정은 메모리, 선택 목록은 sessionStorage, 가상 신청·검수·장비 상태는 IndexedDB를 사용합니다. 로그인 상태와 새 시연 가입 계정은 새로고침하면 초기화됩니다. 이 기능은 실제 학교 계정 인증·서버 권한·Oracle 저장을 대신하지 않습니다.

## 유지해야 할 업무 규칙

- 비로그인 조회·추천·선택을 허용하고 신청 시 인증합니다. 로그인·선택만으로 신청하지 않습니다.
- 승인 대기는 자원 확보가 아닙니다. 승인 시 최신 가능 여부와 기간 중복을 확인합니다.
- 같은 신청 묶음도 항목별로 승인·거절·이용 상태를 관리합니다.
- 출고 당시 구성품 기준을 보존하고, 기본 구성품 수정과 분리합니다.
- 추가 반환은 같은 대여 건에서 이번·누적·부족 수량과 검수 회차를 기록합니다.
- 반납 완료와 장비 점검 완료, 시설의 예정 시간과 실제 시작·종료를 구분합니다.
- 필수 관리 기능 F08·F17 관리 부분·F21은 원본에 화면이 없더라도 후속 필수 범위로 유지합니다.

## 실행·검증 기록

저장소 루트에서 다음 명령으로 화면 미리보기를 실행합니다. JDK 8 이상이 필요하며 npm·Oracle 설치는 필요하지 않습니다.

```powershell
.\preview.cmd
```

- 화면 주소: `http://127.0.0.1:8080/`
- 종료: 서버를 실행한 터미널에서 `Ctrl+C`
- 원본 데이터·추천·가용성·대체 조회 규칙 15개 검증 통과
- 데스크톱 4개·모바일 2개 화면의 렌더·자산 로드·가로 넘침 검증 통과
- 로그인 전후 선택 유지, 자동 신청 방지, 최종 제출, 승인, 학생 내역, 조건·추천 재조회 등 실제 UI 흐름 검증 통과
- 실제 Chrome IndexedDB에서 경쟁 승인·소유권·버전 충돌·출고·보류·추가 반환·점검·시설 이용 등 24개 검증 통과

위 검증은 로컬 화면 시연에 대한 결과입니다. 실제 Oracle·Spring Boot·배포 환경에서 통합 검증한 결과로 취급하지 않습니다.
