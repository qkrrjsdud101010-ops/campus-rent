## 2. Oracle 11g SQL 작성 결과

이 작업은 앞선 `73333ce` 커밋에 이미 포함되어 있다. 기준은 `docs/erd/[New-Era] CampusRent_ERD_20261020.pdf`의 논리·물리 ERD이며, Oracle 11g 실행 검증과 서버 연결은 남아 있다.

- `db/oracle11g/`: 설치 진입점, 기존 객체 충돌 검사, 테이블·제약조건, 관계·인덱스, 시퀀스·INSERT 트리거, 메타데이터 확인, 선택 실행용 무결성 검사.
- 원본 ERD의 26개 테이블·185개 컬럼·자료형·NULL 허용 선언을 유지했다.
- 코드 값·DEFAULT·UQ·CHECK·인덱스 등 ERD에 명시되지 않은 보완 설계는 [SQL 안내](../../db/oracle11g/README.md)에 별도로 설명했다.
- `tools/check-oracle11g-schema.py`의 정적 대조 9개 그룹은 통과했다. 이는 Oracle SQL 실행·PL/SQL 컴파일 검증을 의미하지 않는다.
- 선택 DML 검사 29개는 테스트용 스크립트로 작성했으며 실제 Oracle에서 실행하지 않았다.

### 유지할 설계 기준

- 총 29개 기능(필수 24개·선택 5개)을 유지한다. UX 번호는 개선 추적용이며 F ID·기존 Screen ID를 추가하지 않는다.
- 이 개선을 위해 26개 테이블·185개 컬럼이나 DDL을 변경하지 않는다.
- 승인 대기는 자원을 점유하지 않는다. 반납/이용 조기 완료 후에도 원래 예약 종료까지 확보 기간을 유지한다.
- 시간 구간은 `[시작, 종료)`이고 제출·승인 시 최신 가능 여부를 재검사한다. 시간표의 빈 시간 선택만으로 신청·확보하지 않는다.
- 출고 보존 기준에서 회차별 이번 반환량을 합산하며 과거 기준을 현재 기본 구성품으로 추정하지 않는다.
- 홈은 본인 개별 항목·서버 기준 한국 날짜로 집계하고, 조회 실패를 0건으로 표시하지 않는다. 반납 신청 중인 학생에게 재반납을 요구하지 않는다.
- 공용 시간표 응답에는 타인 신청자·접수번호·활동·목적·내부 메모를 포함하지 않는다.
- 장비 보관 장소를 확정 수령/반납 장소로 표시하지 않는다. 미확인 사진은 기존 아이콘으로 구성한다.
- F08·F17 관리 부분·F21은 원래 남은 필수 관리 화면이며 이번 조회 개선과 별도로 구현한다.

### 검증 결과와 한계

- 독립 검토안의 5개 화면을 360·390·768·1440px에서 확인해 가로 넘침이 없었다.
- 장비 상태 8종, 선택 제거·일정 오류 차단, 시설 빈 시간 조건 확인·구간 밖 입력 차단, 관리자 상태 필터·신청일 정렬을 Chrome에서 확인했다.
- 데스크톱 신청 상세/시간표와 모바일 선택 화면의 캡처를 시각 검토했다.
- 문서 내부 파일 링크와 기능 수(29/24/5), Git 공백 오류를 확인했다.
- 이 결과는 실제 앱 개선 구현, A01~A15 전체 합격, 실제 모바일 기기·서버 권한·Oracle 통합 검증을 의미하지 않는다.

## 4. 한남대학교 간편로그인 검토

### 확인한 사실과 확인이 필요한 부분

2026-10-28 공개 자료에서 다음을 확인했다.

- [공식 하이클래스](https://hiclass.hannam.ac.kr/learningx/main)에 통합 로그인 화면이 있다.
- [일반대학원 공식 접속 안내](https://gra.hannam.ac.kr/notice-2/?mod=document&uid=568)는 포털 로그인 후 하이클래스로 진입하는 경로를 설명한다.
- 조사한 공개 자료에서는 학생 프로젝트용 SSO API·등록 절차·지원 프로토콜을 확인하지 못했다. 학교가 외부 연동을 지원하지 않는다고 확정한 것은 아니다.
- 학교 [공식 IT 문의 안내](https://www.hannam.ac.kr/kor/community/community_03_6_5.html)에 IT콜센터 042-629-7111이 안내되어 있다. 사용자에게 담당 부서 확인 경로를 안내했으며 실제 연락은 하지 않았다.

### 논의한 연동 방향

1. CampusRent에서 학교 계정 로그인 선택.
2. 학교 공식 로그인 화면에서 인증.
3. CampusRent 서버가 학교의 인증 결과를 검증.
4. 학교의 고정 외부 식별자를 내부 사용자와 연결하고 CampusRent 세션을 생성.

학교 비밀번호는 CampusRent에 수집·저장하지 않는 구조로 설명했다. OIDC 또는 SAML을 지원한다면 Spring Security 연동을 검토할 수 있지만, 한남대가 해당 방식을 지원한다고 확인한 것은 아니다. 학교 제공 문서·테스트 환경·서비스 등록·사용자 식별자/소속/재학 속성 제공 여부를 먼저 확인해야 한다. 참고: [Spring OIDC](https://docs.spring.io/spring-security/reference/servlet/oauth2/login/core.html), [Spring SAML](https://docs.spring.io/spring-security/reference/servlet/saml2/login/overview.html).

학교 SSO가 어려우면 학교 이메일로 일회용 인증번호를 받는 간편로그인을 대안으로 논의했다. 이메일 소유 확인만으로 현재 재학 상태가 증명되지는 않는다.

### 아직 변경하지 않은 범위

- 현재 계획서는 실제 학사 계정·SSO를 제외 범위로 유지한다. 사용자의 질문은 도입 가능성 검토이며 구현·필수 범위 추가 확정으로 기록하지 않는다.
- 도입 시 F01·인증 설계와 외부 계정 매핑 구조를 추가 검토한다. 기존 `APP_USER.PASSWORD`의 NOT NULL과 SSO 전용 가입, 이메일 제공 여부·중복 계정 연결 정책도 함께 설계해야 한다.
- 학교 인증 성공으로 CampusRent 관리자 권한을 자동 부여하지 않는다. 관리자 권한은 기존 별도 부여 원칙을 유지한다.
- 학교 로그인 자동화·실제 자격증명 입력·테스트 계정 생성·학교 서비스 등록·메일 발송·DB 변경은 수행하지 않았다.

## 5. 후속 작업

1. 개선 설계를 실제 화면에 단계별 구현한다. 첫 순서는 공통 상태 기준·신청 상세·모바일 선택 목록이다.
2. 서버 기술 버전·데이터 접근 방식을 확정하고 계정·역할·소유권·서비스·DAO를 연결한다.
3. 작성된 SQL을 실제 Oracle 11g 테스트 환경에서 실행·검증하고 승인 경쟁·검수 저장을 통합 시험한다.
4. 학교 간편로그인은 연동 지원 여부를 확인한 뒤 도입 범위·인증 방식·ERD 변경 여부를 정한다.
5. 설계와 구현이 확정된 범위에 맞춰 기존 PPT·Figma·유스케이스 대응을 갱신한다.

`.work/`의 브라우저 프로필·캡처·검증 보조 스크립트·로컬 미리보기 프로세스, 원본 Make ZIP은 커밋 대상에서 제외한다.
