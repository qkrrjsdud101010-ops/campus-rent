# CampusRent 화면 구현

`/purpose`에 **문장 분석 → 결과 비교 → 확인한 항목만 적용 → 추천 구성 보기**를 추가했다. 직접 입력한 인원·준비 항목을 기본 유지하며 시설 허용 목적·날짜·선택 목록은 AI가 변경하지 않는다. 키 미설정 시 기본 규칙 결과로 표시한다. 설정과 검증 범위는 [문장 분석 안내](../SENTENCE_ANALYSIS.md)를 참조한다.

## 현재 구현

React·TypeScript·Tailwind 런타임 없이 HTML·CSS·JavaScript 모듈로 화면을 구현했습니다. 공통 HTML은 `src/main/resources/templates/index.html`, CSS·JavaScript·이미지·폰트는 `src/main/resources/static/`에 배치했습니다. 템플릿의 정적 자원 경로에는 Thymeleaf용 `th:href`·`th:src`를 함께 준비했습니다. `run-server.cmd`는 Thymeleaf로 렌더링하고 Oracle API를 호출합니다. `preview.cmd`는 기존 독립 정적 시연을 제공합니다. 실행·계정·검증 범위는 [서버 개발 안내](../SERVER.md)를 참조하세요.

| 경로 | 화면·동작 |
| --- | --- |
| `/` | 활동 입력·키워드·장비/시설 진입, 로그인 학생의 오늘 건수·다음 할 일 |
| `/equipment` | 원본 장비 7개, 검색·분류, 일정, 가능 여부, 상세·대체 장비·다른 기간 |
| `/facilities` | 원본 시설 5개, 시간·인원·목적, 상세·대체 시설·다른 시간대 |
| `/purpose` | 규칙 기반 활동 분석·확인 질문·추천 이유·시설 수용 인원 검사 |
| 공통 선택 목록 | 항목별 조건 보존·수정·제거, 모바일 하단 목록 열기·대화상자, 신청 시 인증·최종 제출 |
| `/records` | 학생 본인의 진행 중 신청, 승인 전 취소, 장비 반납 신청 |
| `/history` | 완료·거절·취소된 내역, 원래 항목 번호·처리 사유 |
| `/admin` | 관리자 로그인, 개별 승인·거절, 출고·반납 검수·추가 반환·점검, 시설 시작·종료 |
| `/admin/equipment` | 실제 서버에서 장비 등록·수정·구성품·사용 중지·대여 허용, 분류·모델·사양 신규 등록 |
| `/admin/facilities` | 실제 서버에서 시설 정보·요일별 운영 시간·허용 목적·점검 및 중지 구간 편집, 예약 충돌 검사 |
| `/admin/alternatives` | 실제 서버에서 방향이 있는 대체 장비 관계·지정 사유·주요 차이·활성 여부 편집 |

원본 SVG 14개와 로컬 폰트 3개를 그대로 복사했습니다. 시연 자원 이름·사양·구성품·관리번호·추천·대체 규칙은 Make 코드에서 가져왔습니다. 홈과 주요 화면은 데스크톱·모바일에서 확인했습니다.

## 개선 설계(2026-10-28)

[화면 개선 상세 설계](CampusRent_UI_Improvement_Design.md)에 신청 상세·홈 개인 일정·시설 주간 시간표·관리자 조회와 모바일 선택 목록·상태 표현·카드 구성의 7개 개선을 정리했습니다. 상태별 행동, 기존 ERD 매핑, 구현 순서, A01~A15 수용 기준을 포함합니다. 2026-11-18 현재 UX01 신청 상세·UX02 개인 홈·UX05 모바일 선택 목록과 관련 UX06 상태 표시를 구현했습니다. UX03 시설 시간표·UX04 관리자 조회·UX07 카드 위계는 후속 범위이며 PPT·Figma의 수정 완료를 의미하지 않습니다.

신청 상세는 `/records?item={requestItemId}`·`/history?item={requestItemId}`로 특정 항목에 연결하며 현재 상태에 맞는 목록에서 엽니다. 처리 순서·다음 행동·실제 출고/이용 시각·출고 기준·반환 회차·누적 및 부족 수량을 표시합니다. 학생에게는 관리자 내부 검수 메모를 반환하지 않습니다. 홈은 `GET /api/me/summary`로 본인의 오늘 수령·반납 예정·시설 이용 건수와 다음 할 일 최대 3건을 불러옵니다. 카드에서 오늘 해당 내역으로, 할 일에서 항목 상세로 이동합니다.

모바일 하단의 선택 목록은 네이티브 대화상자로 열어 항목 조건 편집·제거·신청을 처리하고 필요한 로그인과 최종 확인으로 연결합니다. 새 기능은 실제 Oracle API 42개·Java 단위 테스트 73개를 통과했지만, 이번 실제 브라우저 검증은 자동화 연결 오류로 수행하지 못했습니다. 렌더링·실기기·키보드 접근성의 통과를 뜻하지 않습니다.

[독립 화면 검토안](campusrent-improvement-wireframes.html)은 파일을 브라우저로 열면 확인할 수 있습니다. 홈·신청 상세·선택 목록·시설 시간표·관리자 화면을 전환하고 예시 상태/조건을 조작할 수 있습니다. 2026-10-28 기준 합성 데이터만 사용하며 기존 시연 저장소·로그인·실제 신청·DB에 연결되지 않습니다. 시간표 단위와 실제 수령·반납 장소 등은 상세 설계의 후속 확인 사항을 적용합니다.

실제 개발 서버(8081)는 Oracle의 APP_USER·신청·출고·반납·시설 이용을 사용합니다. BCrypt 비밀번호, 서버 세션·CSRF·역할·소유권·버전 검사를 적용하며 새로고침 후에도 서버 계정·내역을 유지합니다. 선택 목록만 sessionStorage에 보관합니다. 초기 관리자 정보는 Git 제외 로컬 설정에서 확인하며 학교 SSO는 미구현입니다.

독립 정적 시연(8080)의 로그인·회원가입은 준비된 시연 계정과 메모리상의 프로필로 동작합니다. 비밀번호·인증 토큰을 브라우저 저장소에 기록하지 않고, 로그인 세션·계정 프로필도 별도 영구 저장하지 않습니다. 신청 기록에는 내역 식별을 위한 시연 신청자의 ID·이름을 보존합니다. 선택 목록은 탭의 sessionStorage, 가상 신청·구성품 검수·장비 상태는 IndexedDB에 보존합니다. 새로고침하면 로그인과 새로 가입한 시연 계정은 초기화됩니다. 이 동작은 실제 회원가입·서버 권한 검사·학교 계정 연동을 대신하지 않습니다.

승인 대기는 자원을 확보하지 않으며, 승인 시 최신 예약을 확인합니다. 신청·장비 버전을 비교하고 검수 결과를 트랜잭션으로 저장해 같은 브라우저의 다중 탭 시연도 처리합니다. 출고 기준과 기본 구성품, 이번 반환 수량과 누적 반환 수량, 대여 상태와 장비 점검 상태를 구분합니다.

## 실제 서버 실행

저장소 루트에서 `.\run-server.cmd`를 실행하고 [개발 서버](http://127.0.0.1:8081)를 엽니다. 새 PC 준비는 [서버 안내](../SERVER.md)를 따릅니다. 학생 회원가입과 관리자 초기 계정을 사용합니다. 실제 API 20개·서버 Chrome 화면 20개·단위 테스트 7개를 확인했습니다.

## 독립 시연 실행

JDK 8 이상의 `java`·`javac`를 PATH에 등록하고 저장소 루트에서 실행합니다.

```powershell
.\preview.cmd
```

[로컬 미리보기](http://127.0.0.1:8080)를 엽니다. 서버는 로컬 PC의 8080 포트에서 동작하며 종료는 `Ctrl+C`입니다. 포트를 바꿔야 한다면 미리보기 빌드 후 `java -cp .work/preview PreviewServer 8081 .`처럼 실행할 수 있습니다.

준비된 시연 계정은 루트 README와 화면의 로그인 팝업에서 확인합니다. 학생으로 신청한 뒤 로그아웃하고 관리자 계정으로 로그인하면 해당 항목을 처리할 수 있습니다.

## 검증

검증 코드는 `tools/`에 있으며, JavaScript 검사 실행에는 Node.js 22 이상이 필요합니다. 일반 화면 미리보기에는 Node.js가 필요하지 않습니다.

```text
node tools/check-ui-data.mjs
node tools/check-facility-hours.mjs
node tools/check-personal-home.mjs
node tools/check-ui-browser.mjs
```

앞의 세 검사는 서버 없이 실행하는 순수 검사로 각각 15개·8개·10개입니다. 마지막 브라우저 검사는 미리보기 서버 실행 후 사용합니다. Windows의 기본 Chrome 경로를 찾거나 `CHROME_PATH` 환경변수를 사용합니다. 기존 사용자 브라우저와 분리한 임시 프로필에서 검증하고 종료합니다.

- 원본 데이터·추천·가용성·대체 조회 규칙: 15개 검증 통과
- 데스크톱 4개 화면·모바일 2개 화면: 렌더·이미지 로드·가로 넘침 검증 통과
- 실제 UI 조작: 키워드, 선택 유지, 로그인, 최종 신청, 관리자 승인, 개인 내역, 결과 없음, 인원·추천 재조회 검증 통과
- 실제 Chrome IndexedDB: 중복 승인 경쟁, 소유권, 버전 충돌, 출고 기준, 보류·추가 반환·초과 반환, 점검 완료, 시설 이용 등 24개 검증 통과

결과와 캡처는 `.work/`에 저장되며, 서버·Oracle·실제 학교 운영 환경의 통합 시험을 수행했다는 의미는 아닙니다.

위 목록은 기존 시연 검증입니다. 2026-11-18 새 기능은 Java 단위 테스트 73개·실제 Oracle API 42개(기능 API 31개·개인 요약 9개·시설/대체 관계 동시 충돌 2개)·JavaScript 순수 검사 47개·JAR 패키징을 통과했습니다. 실제 브라우저 검증은 CUA·sky 연결의 `native pipe unavailable (os error 2)`로 수행하지 못했습니다. 새 화면의 렌더링·모바일 실기기·키보드 접근성 검증은 남아 있으며 순수 함수·HTTP 검사는 실제 DOM·브라우저 검증을 대신하지 않습니다. 범위는 [당일 기록](../worklogs/2026-11-18-session.md)을 따릅니다.

## 추가 요청: 면접·기타 활동 추천

홈 또는 `/purpose`에서 면접·모의면접 준비, 스터디, 세미나·행사 등 활동을 입력합니다. **기타 직접 설정**도 자유로운 활동 설명을 유지하며, **공간·영상 촬영·음성 녹음·자료 투사**를 선택해 필요한 구성을 조정합니다. 규칙이 인식하지 못한 활동도 필요 항목을 직접 선택할 수 있습니다. AI 모델을 사용하는 추천이 아닙니다.

활동 설명과 시설의 실제 허용 목적은 별개입니다. 면접을 입력해도 허용 목적을 새로 등록하거나 임의로 바꾸지 않습니다. 시설 신청에는 등록된 허용 목적·인원·일정을 확인해야 합니다. 활동·필요 항목을 바꿀 때 기존 일정·직접 수정한 인원과 허용 목적·이미 담은 선택 목록을 보존합니다.

서버는 `/api/catalog`의 기존 DB `purposeRules`를 사용하고 독립 시연과 구분합니다. Java 전체 79개(기존 73개+카탈로그 6개), 신규 엔진 순수 검사 16개·UI 대역 검사 14개·실제 Oracle 연계 읽기 6개를 통과했습니다. 앞 절의 42개·47개는 앞선 네 단계의 결과로 유지하며 이번 결과와 합산하지 않습니다.

네이티브 Chrome 앱 제어로 `/purpose?activity=면접`의 공간 5개 후보와 실제 허용 목적 미선택 시 선택 차단, 자유 활동 원문의 기타 설정 유지, 활동 변경 시 재조회 안내, 영상·음성 선택 후 카메라·마이크 2개 후보 및 선택 목록 0개 유지 여부를 확인하고 데스크톱 캡처를 검토했습니다. 앞선 네 단계의 브라우저 미검증은 그대로이며 이번 확인은 추천 일부 데스크톱 흐름에 한정합니다. 일정 신청 저장·실제 촬영/녹음은 실행하지 않았고 모바일·전체 키보드 접근성은 미검증입니다.
