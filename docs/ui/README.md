# CampusRent 화면 구현

## 기준 자료

- 개발 명세: [프로젝트 계획서](../New-Era_PROJECT.md), 루트 [README](../../README.md)
- 원본: 로컬 참고 파일 `Implement CampusRent Home Screen (복사).zip` (기존 `*.zip` 규칙에 따라 Git 제외)
- Figma Make 복사본: [소유자 계정의 화면 파일](https://www.figma.com/make/K39IL8xHJP1zJFRITb7PLL/Implement-CampusRent-Home-Screen)

현재 화면은 제공된 ZIP의 코드와 자산을 기준으로 전환했습니다. 이후 Figma 수정 사항은 자동 동기화되지 않습니다. 원본 ZIP은 변경하지 않았고, 작업용 압축 해제본·미리보기 빌드·검증 캡처는 Git에서 제외된 `.work/`에 보관합니다.

## 현재 구현

React·TypeScript·Tailwind 런타임 없이 HTML·CSS·JavaScript 모듈로 화면을 구현했습니다. 공통 HTML은 `src/main/resources/templates/index.html`, CSS·JavaScript·이미지·폰트는 `src/main/resources/static/`에 배치했습니다. 템플릿의 정적 자원 경로에는 Thymeleaf용 `th:href`·`th:src`를 함께 준비했습니다. 현재 미리보기는 정적 HTML을 제공하며 Thymeleaf 엔진이나 Spring Boot를 구동하지 않습니다.

| 경로 | 화면·동작 |
| --- | --- |
| `/` | 원본 홈, 활동 입력·키워드, 장비·시설 진입, 활동별 구성·이용 절차 |
| `/equipment` | 원본 장비 7개, 검색·분류, 일정, 가능 여부, 상세·대체 장비·다른 기간 |
| `/facilities` | 원본 시설 5개, 시간·인원·목적, 상세·대체 시설·다른 시간대 |
| `/purpose` | 규칙 기반 활동 분석·확인 질문·추천 이유·시설 수용 인원 검사 |
| 공통 선택 목록 | 항목별 조건 보존·수정·제거, 신청 시 인증, 별도의 최종 제출 |
| `/records` | 학생 본인의 진행 중 신청, 승인 전 취소, 장비 반납 신청 |
| `/history` | 완료·거절·취소된 내역, 원래 항목 번호·처리 사유 |
| `/admin` | 관리자 시연 로그인, 개별 승인·거절, 출고·반납 검수·추가 반환·점검, 시설 시작·종료 |

원본 SVG 14개와 로컬 폰트 3개를 그대로 복사했습니다. 시연 자원 이름·사양·구성품·관리번호·추천·대체 규칙은 Make 코드에서 가져왔습니다. 홈과 주요 화면은 데스크톱·모바일에서 확인했습니다.

로그인·회원가입은 준비된 시연 계정과 메모리상의 프로필로 동작합니다. 비밀번호·인증 토큰을 브라우저 저장소에 기록하지 않고, 로그인 세션·계정 프로필도 별도 영구 저장하지 않습니다. 신청 기록에는 내역 식별을 위한 시연 신청자의 ID·이름을 보존합니다. 선택 목록은 탭의 sessionStorage, 가상 신청·구성품 검수·장비 상태는 IndexedDB에 보존합니다. 새로고침하면 로그인과 새로 가입한 시연 계정은 초기화됩니다. 이 동작은 실제 회원가입·서버 권한 검사·학교 계정 연동을 대신하지 않습니다.

승인 대기는 자원을 확보하지 않으며, 승인 시 최신 예약을 확인합니다. 신청·장비 버전을 비교하고 검수 결과를 트랜잭션으로 저장해 같은 브라우저의 다중 탭 시연도 처리합니다. 출고 기준과 기본 구성품, 이번 반환 수량과 누적 반환 수량, 대여 상태와 장비 점검 상태를 구분합니다.

## 실행

JDK 8 이상의 `java`·`javac`를 PATH에 등록하고 저장소 루트에서 실행합니다.

```powershell
.\preview.cmd
```

[로컬 미리보기](http://127.0.0.1:8080)를 엽니다. 서버는 로컬 PC의 8080 포트에서 동작하며 종료는 `Ctrl+C`입니다. 포트를 바꿔야 한다면 미리보기 빌드 후 `java -cp .work/preview PreviewServer 8081 .`처럼 실행할 수 있습니다.

준비된 시연 계정은 루트 README와 화면의 로그인 팝업에서 확인합니다. 학생으로 신청한 뒤 로그아웃하고 관리자 계정으로 로그인하면 해당 항목을 처리할 수 있습니다.

## 검증

검증 코드는 `tools/`에 있으며, JavaScript 검사 실행에는 Node.js 22 이상이 필요합니다. 일반 화면 미리보기에는 Node.js가 필요하지 않습니다.

```text
node tools/check-ui-data.mjs
node tools/check-ui-browser.mjs
```

두 번째 검사는 미리보기 서버 실행 후 사용합니다. Windows의 기본 Chrome 경로를 찾거나 `CHROME_PATH` 환경변수를 사용합니다. 기존 사용자 브라우저와 분리한 임시 프로필에서 검증하고 종료합니다.

- 원본 데이터·추천·가용성·대체 조회 규칙: 15개 검증 통과
- 데스크톱 4개 화면·모바일 2개 화면: 렌더·이미지 로드·가로 넘침 검증 통과
- 실제 UI 조작: 키워드, 선택 유지, 로그인, 최종 신청, 관리자 승인, 개인 내역, 결과 없음, 인원·추천 재조회 검증 통과
- 실제 Chrome IndexedDB: 중복 승인 경쟁, 소유권, 버전 충돌, 출고 기준, 보류·추가 반환·초과 반환, 점검 완료, 시설 이용 등 24개 검증 통과

결과와 캡처는 `.work/`에 저장되며, 서버·Oracle·실제 학교 운영 환경의 통합 시험을 수행했다는 의미는 아닙니다.

## 다음 단계

1. 화면 검토 결과를 반영합니다.
2. JDK·Spring Boot 버전과 MyBatis/JDBC 방식을 팀 기준으로 확정합니다.
3. [ERD 기반 Oracle 11g SQL](../../db/oracle11g/README.md)을 실제 DB에서 검증하고, 확정한 코드 규약·초기 데이터를 반영합니다.
4. Spring MVC·Thymeleaf, 서버 세션·권한, 서비스·DAO를 연결합니다. `store.js`의 시연 저장 기능을 서버 호출로 전환하되 화면 입력·처리 상태를 유지합니다.
5. 승인 경쟁·검수 상태 변경을 실제 DB 트랜잭션으로 구현하고 통합 검증합니다.

원본 Make에 없던 장비 관리(F08), 대체 관계 편집(F17 관리 부분), 시설 운영 관리(F21) 화면과 추천 기준 관리 범위는 별도 설계·후속 개발 대상입니다. ERD 기반 SQL·Oracle 연결·최종 서버 인증·배포는 아직 구현하지 않았습니다.
