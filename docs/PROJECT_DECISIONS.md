# CampusRent 최신 결정 사항과 교차 확인

기록일: 2026-11-18. 사용자가 전달한 최신 대화·결정을 기존 소스·문서·산출물·저장된 검증 기록과 대조했다. 이번 범위는 현황 정리와 문서 갱신이다. 배포·서버 재시작·DB 접속 및 변경·유료 API 호출·포스터 및 프로그램 수정·커밋·푸시는 수행하지 않는다.

이 문서의 최신 결정은 같은 주제에 관한 이전 제안보다 우선한다. 다만 **팀이 정한 방향**, **현재 파일에 실제 적용된 내용**, **실행 기록으로 확인된 결과**는 구분한다. 프로젝트 기준 문서의 실제 경로는 [New-Era_PROJECT.md](New-Era_PROJECT.md)이며 루트 `PROJECT.md`는 별도로 없다.

## 4. Figma 프리뷰와 GitHub 공개

**Figma 프리뷰 링크는 행사 당일 안내한다.** 행사 날짜와 최종 공개 URL은 이번 결정에서 확정되지 않았다. 과거 행사 공지 날짜나 README에 있던 Make 작업 링크를 최종 공개 일정·URL로 대신하지 않는다. 현재 포스터에 Figma QR이 없다는 사실은 오류나 미완성 판정 근거가 아니다.

행사 안내 전에 최종 링크가 프리뷰에 접근하는 용도인지, 열람 권한이 적절한지, 다른 기기·계정에서 화면 이동이 동작하는지 확인한다. 이번에는 링크 권한 변경이나 외부 접속 시험을 하지 않는다.

**GitHub QR은 최신 디자인에서 유지한다.** 새 PNG 전체를 로컬 QR 판독기(zxing-cpp 3.1.1)로 읽어 유효한 QR 1개의 실제 주소를 확인했다: [박건영 CampusRent 프로젝트 저장소](https://github.com/qkrrjsdud101010-ops/campus-rent). 개인 프로필 주소가 아니며 카드에 인쇄된 계정·저장소명 및 현재 Git remote와 일치한다. 이는 실제 QR 바이트 해독 결과이며, 이번에 웹사이트 접속·다른 기기에서의 스캔·행사 현장 인쇄물 판독까지 검증한 것은 아니다. 판독 도구는 Git 제외 `.work/qr-inspection-deps`에만 설치했으며 앱 의존성을 변경하지 않았다.

### 비밀 설정 연결

`application-local.properties`는 `.gitignore`에서 제외되고 pom.xml의 `application-local.*` 제외 규칙으로 JAR에도 들어가지 않는다. 따라서 배포 때 이 로컬 파일이 전달된다고 가정하면 안 된다. 배포 플랫폼의 비밀 설정 또는 환경별 설정 공급 방식과 애플리케이션 설정 항목을 별도로 연결해야 한다.

필요한 항목은 `spring.datasource.url/username/password`, `campus.analysis.enabled/provider/openai.api-key/openai.model` 등이다. 현재 공개 설정에는 `OPENAI_API_KEY`, `OPENAI_MODEL`, `CAMPUS_ANALYSIS_ENABLED`, `CAMPUS_ANALYSIS_PROVIDER` 참조가 있다. 실제 값·비밀번호·키는 문서·로그·화면에 쓰지 않는다. 배포 시에도 DDL 자동 실행·초기 관리자 생성·데모 시드 입력을 자동으로 활성화하지 않는다.

### 배포 후 검증할 흐름 — 아직 수행하지 않음

1. 로그인·로그아웃·학생/관리자 권한·소유권 구분.
2. 시설·장비 목록·상세·가용성 조회.
3. 신청 저장과 관리자 화면 반영.
4. 승인 시 중복 검사와 예약 확보, 동시 승인 처리.
5. 출고 기준 구성품, 반납·보류·추가 반환 처리와 상태 일관성.
6. GPT 문장 분석·사용자 확인·추천 연결, 실패 시 정직한 규칙 분석 대체.
7. 다른 기기·계정에서 조회하는 데이터·상태의 일관성.

## 6. ERD·SQL 유지

이번 정적 교차 확인에서 `01_tables.sql`은 **26개 테이블·185개 컬럼**, `03_sequences.sql`은 **17개 시퀀스와 대응 트리거**이며 기존 ERD와 맞는다. `tools/check-oracle11g-schema.py`의 기존 정적 검사도 통과했다. 이는 로컬 파일 검사이며 이번 Oracle 접속·객체 재생성·SQL 실행 결과가 아니다.

문장 분석 결과를 영구 저장하지 않는 현재 구조와 배포 장소 변경만으로는 ERD·테이블 생성 SQL을 변경하지 않는다. 조회 조건·키워드·추천 규칙 데이터의 변경은 테이블 구조 변경과 구분한다. 분석 이력 보관 등 새로운 저장 요구사항이 생길 때 보관 목적·데이터·기간·권한을 먼저 정하고 ERD·SQL 변경 필요성을 검토한다.
