# CampusRent

**이용 목적에 맞는 교내 시설·장비 추천 및 대여·예약 관리 시스템**

> 정보시스템프로젝트캡스톤디자인 | New-Era 팀  
> 분석·설계 문서를 기반으로 Spring Boot·Oracle 시스템을 개발하는 프로젝트입니다.

## 1. 프로젝트 소개

CampusRent는 학생이 필요한 교내 시설·장비를 **직접 검색**하거나, **활동 목적과 참여 인원 등에 맞는 추천**을 받아 적합한 자원을 선택하고 대여·예약을 신청할 수 있도록 지원하는 웹 기반 정보시스템입니다. 관리자는 신청 승인·거절, 장비 출고·반납, 시설 이용 상태 등을 관리합니다.

**핵심 차별점은 목적 기반 탐색입니다.** 예를 들어 학생이 '학생회 회의 6명' 또는 '과제 영상 촬영'을 입력하면, 등록된 용도·키워드·인원 조건에 따라 적합한 공간과 장비, 추천 이유를 안내합니다. 필요한 자원을 이미 알고 있다면 이름이나 분류로 직접 검색할 수도 있습니다.

> 자원 추천은 등록 규칙·실제 허용 목적·사용자 조건으로 결정합니다. 선택형 **AI 문장 분석 → 사용자 확인 → 기존 추천** 연결을 추가했으며, 키가 없거나 분석에 실패하면 기본 규칙을 사용합니다. 실제 학교 자원 및 운영 정책은 확인이 필요하며 가상 시설·장비가 포함됩니다. [문장 분석 설정](docs/SENTENCE_ANALYSIS.md)

## 2. 프로젝트 목표

- 이용 목적과 인원에 맞는 시설·장비를 추천하고 추천 이유를 제시
- 시설·장비 직접 검색, 상세 정보 및 이용 조건 확인 지원
- 이용 불가 시 다른 일정 또는 대체 시설·장비 조회 지원
- 선택 목록에서 필요한 항목과 조건을 확인한 뒤 개별 신청
- 관리자 승인·거절, 장비 출고·반납·점검 및 시설 이용 이력 관리

## 9. 개발 준비 및 협업

**수정·공유 원칙:** 각자 VS Code에서 사용하는 로컬 작업 폴더의 파일을 수정하고, 로컬 Git으로 Commit·Push합니다. GitHub에 직접 로그인해 브라우저에서 파일을 수정하지 않습니다. AI 도구도 같은 로컬 저장소에서 작업합니다.

1. `docs/New-Era_PROJECT.md`, Use Case, ERD, Figma Make 자료를 저장소에 정리합니다.
2. 팀별 개발 도구와 역할 분담을 협의하고 README를 갱신합니다.
3. 팀원들이 저장소를 Clone하여 동일한 분석·설계 문서를 공유합니다.
4. 기능 구현 시 Use Case·ERD·화면설계의 명칭과 범위를 일치시킵니다.
5. 구현·검증 결과에 따라 문서와 소스코드를 함께 업데이트합니다.

**주의:** 화면 시연 구현과 최종 서버·DB 연동 완료는 구분합니다. 이 README의 기능 목록은 프로젝트 목표를 포함하며 전체 기능 구현 완료를 의미하지 않습니다.

## 10. 실제 개발 서버 실행

이 PC는 실행 도구와 Oracle 로컬 설정 준비를 완료했습니다. 저장소 루트에서 실행하고 [개발 서버](http://127.0.0.1:8081)를 엽니다.

```powershell
.\run-server.cmd
```

학생은 화면에서 회원가입합니다. 관리자 로그인 정보는 Git 제외 `src/main/resources/application-local.properties`의 `campus.bootstrap.admin.email`·`campus.bootstrap.admin.password`에서 확인합니다. DB 로그인과 별개이며 공개 시연 계정은 서버에 적용되지 않습니다. 자세한 준비·테스트·패키징과 범위는 [서버 개발 안내](docs/SERVER.md)를 참조하세요.

관리자 로그인 후 **신청 관리 → 장비 관리** 또는 `/admin/equipment`에서 분류·모델·사양 등록, 장비 등록·수정, 구성품 편집, 대여 허용·사용 중지를 처리할 수 있습니다. 공유 모델 정의는 새 모델 등록 후 해당 장비에 선택하는 방식입니다.

**시설 운영 관리**(`/admin/facilities`)에서는 시설 기본 정보·요일별 시간·허용 목적·점검 및 중지 구간을 편집합니다. 승인된 예약이나 진행 중 이용을 무효화하는 변경은 거부하며, 신청을 자동 취소하지 않습니다. **대체 장비 관리**(`/admin/alternatives`)에서는 원래 장비에서 대체 장비로 향하는 관계와 지정 사유·주요 차이·활성 여부를 편집합니다. 두 관리 화면은 실제 서버에서 사용하며 기존 26개 테이블·17개 시퀀스를 그대로 사용합니다.

학생의 `/records`·`/history` 상세는 실제 처리 이력·출고 기준·누적 반환·부족 수량과 상태별 다음 행동을 표시합니다. 새 화면의 검증 상태와 남은 7개 UX 개선 범위는 [화면 안내](docs/ui/README.md)에서 구분합니다.

학생 로그인 홈에는 한국 시각 기준 오늘의 수령·반납 예정·시설 이용 건수와 다음 할 일 최대 3건을 표시합니다. 카드에서 해당 내역으로 이동합니다. 모바일 선택 목록은 하단 목록 열기에서 항목 편집·제거·신청, 필요한 로그인과 최종 확인으로 이어집니다. 화면 렌더링·실기기·키보드 접근성은 이번 검증에서 확인하지 못했습니다.

11월 18일 추가 요청으로 목적별 추천에 **면접·모의면접 준비, 스터디, 세미나·행사**와 **기타 직접 설정**을 보강했습니다. 활동을 자유롭게 쓰고 공간·영상 촬영·음성 녹음·자료 투사 중 필요한 준비를 고릅니다. 활동 설명과 시설의 실제 허용 목적을 구분하며, 면접을 학교의 허용 목적으로 자동 등록하지 않습니다. 기존 일정·직접 수정한 인원·허용 목적·선택 목록을 유지하는 흐름입니다. AI 모델 대신 규칙과 사용자의 필요 선택을 사용하고 서버의 기존 DB 추천 규칙을 연결합니다.

추가 개선 후 Java 전체 79개(기존 73개+신규 6개), 추천 엔진 16개·UI 대역 14개·실제 Oracle 연계 읽기 6개와 JAR 패키징을 통과했습니다. Chrome에서 면접 공간 후보·기타 원문 유지·영상/음성 장비 선택을 데스크톱에서 확인했습니다. 이번 추가 작업은 DB 쓰기·DDL·신청 저장을 하지 않았으며 모바일·전체 키보드 검증은 남아 있습니다. 앞선 네 단계의 42개·47개 결과와 별도로 기록합니다.

## 11. 독립 화면 미리보기 실행

JDK 8 이상(`java`, `javac`가 PATH에 등록된 환경)에서 저장소 루트의 터미널로 실행합니다. npm 패키지나 Oracle 설치는 필요하지 않습니다.

```powershell
.\preview.cmd
```

브라우저에서 [http://127.0.0.1:8080](http://127.0.0.1:8080)을 엽니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다. 실제 Oracle에 연결하는 Spring Boot 개발 서버는 위 10절의 `run-server.cmd`로 실행합니다.

8080 독립 시연에서는 홈, 장비·시설 대여, 목적별 추천, 선택 목록·최종 신청, 학생 신청 현황·과거 내역, 로그인·학생 회원가입, 관리자 승인·검수·시설 이용 처리를 확인할 수 있습니다. 가상 신청은 해당 브라우저의 IndexedDB에 저장하고 로그인·시연 회원가입 계정은 새로고침 시 초기화됩니다. 실제 계정 인증·서버 권한 검사·Oracle 저장은 8081 개발 서버에서 사용합니다.

| 구분 | 시연 이메일 | 시연 비밀번호 |
| --- | --- | --- |
| 학생 | `demo@campusrent.example` | `Campus123!` |
| 다른 학생 | `other@campusrent.example` | `Campus123!` |
| 관리자 | `admin@campusrent.example` | `CampusAdmin123!` |

구현 범위와 검증 방법은 [화면 구현 안내](docs/ui/README.md)를 확인합니다.
